# InboxPilot AI — Public Demo

A browser-accessible demonstration of InboxPilot AI, a local-first email assistant concept for organising conversations, identifying messages that may need a reply, checking follow-ups, and preparing draft wording for human review.

## Live demo scope

- Uses fictional sample emails only.
- Demonstrates inbox classification, priority/deadline heuristics, follow-up views, reply suggestions, reply-quality checks, activity history, and human review actions.
- Reply suggestions use transparent Python rules in this public demo; they are not generated by an LLM.
- Gmail integration, local Qwen/LM Studio, automatic sending, and Gmail draft creation are disabled in the public demo.
- The desktop edition can connect to a user's own local LM Studio and read-only Gmail bridge. Never add personal Gmail credentials or mailbox exports to this repository.

## Deploy on Render

1. Create a public GitHub repository and upload the files in this folder.
2. Ensure `gmail_config.json`, `inboxpilot.db`, and any personal email exports are not committed. The `.gitignore` excludes these files.
3. In Render, choose **New + → Blueprint** and connect the GitHub repository.
4. Render reads `render.yaml` and creates the web service.
5. Wait for deployment, then open the `onrender.com` URL shown by Render.
6. Test the dashboard, inbox, triage, reply suggestion, quality check, and reset-demo controls.

## Run locally

Requires Python 3.9+. Run `python app.py` and open `http://127.0.0.1:10000`.

## Notes

The demo uses SQLite in the service filesystem. On Render's free web service, local filesystem data is ephemeral and may reset when the service restarts or redeploys. The demo is intended for evaluation, not production mailbox storage. Public visitors share the demo workspace, so do not enter personal or confidential information.
